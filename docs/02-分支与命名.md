# 02 · 分支与命名

## 当前分支

| 分支 | 目标 MC | 格式号 | `pack.mcmeta` 的 version | 状态 |
| --- | --- | --- | --- | --- |
| `master` | 最新（**注意：内容目前仍是 1.16.5 时代**） | 6 | `"test"` | 待手动带到最新版 |
| `1.16.5` | 1.16.5 | 6 | `"test"` | 内容与 master 当前一致；上次发布 v8.7 |
| `1.15.2` | 1.15.2 | 5 | `"v7.0 for MC1.15"` | 冻结 |

> 仓库里只保留 **`master` 与各版本线**。已清理的历史分支：`v8.5-or-v8.6`（2023 年的旧命名分支，
> 0 独有提交、本是 master 的祖先）、`feat/version-lines`（废弃的单主干方案）。
> 合并后的主题分支（如文档分支）也随手删掉。

## 命名规范

- **分支**：**直接用该 MC 大版本的最终补丁号当名字** —— 不带 `mc` 前缀、不带 `v`：
  `1.15.2`、`1.16.5`、`1.17.1`、`1.18.2`、`1.19.4`、`1.20.6`、`1.21.11`、`26.1.2`、`26.2`、`26.3`。
  用**最终补丁号**而不是大版本号（写 `1.16.5`，不写 `1.16`）。
- **`master` 不加后缀**：它永远代表"最新"。
- 分支与 tag 不会撞车：分支是纯版本号（`1.16.5`），tag 一律带 `v` 前缀（`v8.8-1.16.5`）。
- 分支名就是**目标 MC 版本**，包版本号（v8.8 之类）**不进分支名** —— 一个 MC 版本只有一条线。

## 包版本号

**每条分支独立计数**：

| 分支 | 已发布到 | 下一条 |
| --- | --- | --- |
| `1.15.2` | v7.0（2022-10） | 除非要重发，否则不动 |
| `1.16.5` | v8.7（2025-02） | v8.8 |
| `master`（最新线） | — | 按最新线自己的历史决定 |

所以同一个 `v9.0` 在不同分支下内容不同 —— 看 tag / 资产名里的 MC 目标。`pack.mcmeta` 的
`version` 字段用 `v<包版本> for MC<目标版本>` 形式（例：`v8.8 for MC1.16.5`）。

## tag 与 Release 命名（**重要**）

git tag 是全仓库唯一的。两条分支都发 `v9.0` 必然撞车，所以新发版一律带上目标版本：

- **tag**：`v<包版本>-<目标版本>` —— 例 `v8.8-1.16.5`、`v9.0-26.3`
- **Release 资产名**：`FPP_v<包版本>_for_MC<目标版本>.zip` —— 例 `FPP_v8.8_for_MC1.16.5.zip`
  （沿用历史风格 `FPP_v8.4_for_MC1.16.zip`，只是把目标版本写全到补丁号）

推 tag 时注意：tag 是打在**该分支的提交**上的，别打错分支。

## 历史 tag（保持原样，不要重命名已发布的 tag）

| tag | 实际内容 | 资产名 |
| --- | --- | --- |
| `v7.0` | MC1.15（1.15.2） | `FPP_v7.0_for_MC1.15.zip` |
| `v8.0` … `v8.4` | MC1.16 | `FPP_v8.x_for_MC1.16.zip` |
| `v8.5` | MC1.16 | `FPP_v8.5_for_MC1.16.zip` + `BRP_v8.5_for_MC1.16.zip` |
| `v8.6` | **BRP 扩展包**（不是 FPP） | `BRP_v8.6_for_MC1.16.zip` |
| `v8.7` | MC1.16（1.16.5） | `FPP-v8.7-1.16.5.zip` |

> 历史命名并不统一（`FPP_v8.4_for_MC1.16` / `FPP-v8.7-1.16.5` 混用），
> 而且 `v7.0`（MC1.15）在时间上**晚于** `v8.0`（MC1.16）—— 因为 1.15 支持是后补的。
> 这些都保持原样，新发版照上面的规范来。

## 三个包

| 目录 | 说明 |
| --- | --- |
| `FPP/` | 冻梨子材质（主包），本套文档的对象 |
| `PPP/` | 炫梨子拓展包（PBR），伴随 FPP 发布，未纳入这套版本线 |
| `BRP(deprecated)/` | 血红梨扩展包，已废弃，不要动 |

## 远端

| 远端 | 仓库 | 用途 |
| --- | --- | --- |
| `origin` | `TecoStudio/Frozen_Pear_Pack` | **主仓库**：推主题分支、开 PR、发 Release 都在这里；`master` 有分支保护（必须走 PR） |
| `fork` | `LIPiston/Frozen_Pear_Pack` | 自己的 fork，只作备份 / 查历史，**不要再往它提交** |

**只在一个仓库提交** —— 同一份内容两边都提交，两个仓库就会真分叉，之后只能靠 patch 搬。

# 文档索引（FPP 多版本分支方案）

一个材质包要同时跟上多个 Minecraft 大版本。本仓库用**每个 MC 版本一条 git 分支**来管理：

- **`master`** —— 永久跟随**最新** MC 版本（手动更新，不带版本后缀）
- **`<版本号>`** —— 每个老版本一条分支，分支名直接用该 MC 版本的最终补丁号
  （`1.16.5`、`1.15.2`、以后的 `1.21.11`、`26.3`），内容冻结在该版本
- 已发布的东西用 **tag + GitHub Release** 冻结

> 给 AI / 自动化 agent 的入口是仓库根目录的 [AGENTS.md](../AGENTS.md)（红线 + 路由）；
> 这里是给人读的正文。

## 更新流程（日常工作就这四条）

1. **改内容**：切到**目标版本的分支**（`master` = 最新版；`1.16.5`、`1.15.2` = 老版本线）→ 开一个主题分支
   → 改 `FPP/` → 开 PR 合并回该分支。**不要在 `master` 上直接提交**（服务端有保护）。
2. **跨版本通用改动**（贴图大多属于这类）：在一条线上改好后，用 patch 同步到其它还在维护的线 ——
   **不要 merge / rebase 两条版本线**，见 [01](01-分支模型与纪律.md)。
3. **发版**：改 `FPP/pack.mcmeta` 的 `version` → 打包 → 打 tag `v<包版本>-<目标版本>` → 发 GitHub Release，
   见 [03](03-日常流程.md)。
4. **核验**：发版前跑 [07](07-核验一条分支.md) 的脚本，确认没有"路径变了导致贴图悄悄不生效"。

**最新 MC 版本换代时**：把 `master` 的内容换成新版本（同时改 `pack_format`），旧内容此时已经有自己的
版本线接着 —— 见 [04](04-开一条新版本分支.md)。

## 真值来源

文档会漂移，**以这些为准**：

| 内容 | 真值在哪 |
| --- | --- |
| 某条分支的目标 MC 与格式号 | 该分支的 `FPP/pack.mcmeta` |
| 有哪些分支 | `git branch -r` |
| 每个 MC 版本的最终补丁号、格式号 | [05-pack.mcmeta-与格式号](05-pack.mcmeta-与格式号.md)（含核实来源） |
| 已发布的版本 | GitHub Releases：`TecoStudio/Frozen_Pear_Pack` |
| 历史上发布过什么 | `git tag`（v7.0 … v8.7） |
